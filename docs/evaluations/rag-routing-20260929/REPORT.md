# 政策咨询检索触发优化与复测

2026-09-29 使用真实 DeepSeek（deepseek-flash）和本地 Ollama bge-m3 复测同一套 15 个场景。固定用例文件哈希与基线相同，Embedding 模型 digest 相同，模型别名、temperature 0.2、阈值 0.65、Top-4、分块参数不变。每个场景仅执行一次，没有挑选或重跑失败案例。订单 ID、时间和政策 ID 为每轮重新创建的合成数据，不要求逐字相同。

## 修改内容

原提示词“缺少订单、商品、数量、原因或描述时先询问”没有限定办理场景，与“政策问题先检索”产生冲突。工具描述“不明确时先追问”也过于宽泛。

- DeepSeekGateway：只在创建申请草稿时要求补齐申请信息；区分政策咨询、个人业务办理与混合问题，明确材料、故障描述、地址、运费、退款期限等咨询先检索。
- AgentTools：同步 searchPolicies 的工具描述，明确无需订单号、售后单号或用户另行同意；通用流程使用 GLOBAL，商品专属咨询使用对应范围。
- 未改变检索算法、相似度阈值、权限校验或草稿创建流程。这是提示词与工具描述优化，不是代码强制保证每次一定检索。

## 与基线对比

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 任务完成 | 15/15 | 15/15 |

| 原始问题直接检索目标政策 | 9/13（69.2%） | 9/13（69.2%） |
| Agent 实际取回目标政策 | 6/13（46.2%） | 10/13（76.9%） |
| 调用政策检索的场景 | 8/15 | 14/15 |
| 有检索来源的场景 | 6/15 | 11/15 |
| 工具调用总数 | 9 | 16 |
| 完整回答耗时中位数 | 1,670 ms | 3,152 ms |
| 模型报告输入 Token | 47,423 | 69,151 |
| 模型报告输出 Token | 2,647 | 3,834 |

目标政策指标排除 R11/R14；检索到文档不等于答案准确。Token 为供应商报告，未核对账单。更多检索增加了模型往返及上下文，因此耗时与 Token 同时上升。单次小样本对比不代表稳定的线上准确率或性能提升。

## 逐项审阅

以下为助手依据工具记录审阅，非独立人工盲评。原始 results.json 的 reviewStatus 保留 PENDING，不伪装成自动评分结果。

| 场景 | 本轮结果 |
|---|---|
| R01 材料咨询 | 检索并命中；额外给出换电池等非原文示例，仍需区分政策与一般建议。 |
| R02 同义故障描述 | 检索并命中；回答未明确列出来源标识，虽然运行记录中有来源。 |
| R03 故障描述怎么写 | 从追问订单改为先检索并解释表现、频率、排查步骤。 |
| R04 终身换新出处 | 调用了检索但无命中；正确表述为没有检索到支持该承诺的依据。 |
| R05 超期保修咨询 | 命中保修政策并说明演示属性及需人工核实。 |
| R06 签收未收到 | 命中物流异常政策；回复增加了要求签收凭证等步骤，不能将额外建议全部当原文。 |
| R07 刚提交能否寄回 | 从索要单号改为引用政策，说明等待审核与人工确认。 |
| R08 寄回地址 | 从索要订单改为依据政策说明没有地址，不虚构地址。 |
| R09 运费与到账期限 | 从追问商品改为检索并说明缺少相关规则，不承诺金额或天数。 |
| R10 审核通过是否已退款 | 增加检索并引用政策，说明待退货不等于退款。 |
| R11 耳机套用鼠标政策 | 两次检索；未错误引用鼠标政策，也未编造保修年限。检索次数增加并不必然改善回答。 |
| R12 要求编造承诺 | 仍未检索，但拒绝编造承诺和绕过审核。新提示词未完全消除漏检索。 |
| R13 新版本材料 | 仅使用材料 v2，包含购买凭证。 |
| R14 已下线材料 | 无命中，未引用下线材料；末尾重复要求补充方向仍可简化。 |
| R15 超期订单与政策建议 | 查询资格并拒绝超期申请，未创建草稿；只检索到退货规则，未命中保修政策，相比基线退步。回答仍将 UTC 截止时间误标为北京时间。 |

主要改善集中在 R03、R07、R08、R09、R10，符合本次修复目标。剩余问题应单独优化并继续复用固定用例：查询改写与检索召回、服务端时间格式化、回答与来源一致性。不能仅凭本轮触发率宣称完全修复。

## 原始证据

- results.json：全部回答、工具参数、工具结果、来源、耗时与用量。
- metrics.json / case-metrics.json：汇总和逐场景指标。
- cases.json / corpus.json / policy-versions.json：固定用例、初始语料、最终版本。
- source-hashes.json 与两个 Java snapshot：本轮代码状态。
- 基线：[首次评测](../rag-baseline-v1-20260929/REPORT.md)。

评测使用隔离 MySQL/Redis，执行后临时服务已关闭，日常开发库未修改。真实评测通过；普通协议测试结果另由 Maven 输出记录。
