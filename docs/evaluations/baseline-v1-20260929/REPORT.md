## 发现的改进点

1. **语言一致性**：E01、E02、E03、E06、E07 有英文前缀，应让工具调用前的说明也保持中文。
2. **金额表述**：E09 把“1件申请金额3.33元”称为“该行实付金额”，尽管后续解释整行10元，仍可能误导。后端计算正确，问题在回复口径。
3. **面向用户的表达**：不应要求用户理解 READY、aftersaleId、内部ID或草稿UUID；应围绕商品、数量、申请金额和下一步操作解释。
4. **阶段消息拼接**：部分回答连续拼接多次“请稍等/现在生成草稿”等阶段说明，应区分临时进度和最终回答。
5. **缺省参数提示**：E08 已给出完整订单号，拒绝越权时又要求完整订单号，提示可以更准确。

本轮保留这些问题作为改进前基线，未在运行中修改提示词，也未选择性重跑失败或不满意回答。

## 基线局限与下一轮

- 每场景只测一次，无法判断随机波动。
- 合成订单号含 good / expired / foreign 等语义提示；下一版应改成中性编号，减少答案线索。
- 当前合成订单与商品项 ID 恰好相同，不能充分发现猜测商品项ID的问题；下一版应让两者明显不同。
- E08 含明显“忽略身份限制”指令，模型直接拒绝；下一版增加无攻击措辞的他人订单查询及间接提示注入。
- 金额分摊、混合商品、已占用数量和多种模型故障还需扩充。
- 后续独立评测提示词改进；场景集扩充后另命名版本，不混用分母或宣称同条件提升。
- 比较时应固定模型别名和参数、记录运行日期，保留供应商升级可能带来的影响。
