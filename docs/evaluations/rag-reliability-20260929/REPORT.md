# RAG 回答可靠性优化复测

2026-09-29 使用真实 DeepSeek（deepseek-flash）与本地 Ollama bge-m3 完成固定 15 场景。用例文件哈希、模型别名及 Embedding digest 与上一轮一致；temperature、Top-K、相似度阈值及语料规则不变。各场景执行一次，不挑选结果，不重跑付费场景。合成订单、文档 ID 和时间随运行重新创建。

## 本轮实现

1. **资格截止时间由服务端格式化**：AgentEligibilityVO 将截止时间转换为 Asia/Shanghai，包含北京时间和 UTC+08:00。仅调整模型工具返回，原业务 API 的时间类型不变；null 保持 null。其他工具时间仍保留原始时区，提示词禁止直接把 UTC 标为北京时间。
2. **混合问题分主题检索**：订单资格交给业务工具；超期后的处理建议单独查询保修。运费与到账时间等不同子问题分别检索，避免一段无关来源被当成完整依据。
3. **空结果有界改写**：工具新增 fallbackQuestion，由模型提供同义表达。AgentPolicySearch 每轮最多执行一次额外检索，只有空结果才触发，不改变 scope、阈值或发布过滤，不重试服务故障。普通知识库查询 API 不变。全轮原有 8 次工具调用上限仍有效；一次额外向量检索不等于额外工具调用。
4. **回答依据约束**：政策要求、承诺、期限、步骤需对应本轮来源；填写示例需标注并让用户替换为实际情况；一般建议与政策区分；检索不足不得推断商家没有规定。此部分由提示词约束，不能保证模型每次完全遵守。

## 逐项审阅

审阅由助手对照工具证据完成，不是独立人工盲评。原始记录的 reviewStatus 保持 PENDING，未伪造综合准确率。

| 场景 | 结果与限制 |
|---|---|
| R01 故障材料 | 命中，保留政策要求，未再扩展换电池/驱动等具体排查办法。 |
| R02 连击材料 | 命中，列明原文三类描述要求，这次补上来源标识。 |
| R03 故障描述 | 命中，并明确“填写示例（请替换为真实情况）”；前面的分项仍扩展了接口、电池等例子，政策与建议区分尚非完全严格。 |
| R04 终身免费换新 | 原查询和同义改写均未命中；回复依据不足，不承诺，也不据此断言商家没有规定。 |
| R05 超期保修 | 命中保修政策，说明人工核实、无统一年限与演示属性。 |
| R06 签收未收到 | 命中物流政策，本轮未再添加“要求签收凭证”的原文外步骤。 |
| R07 提交后寄回 | 引用政策说明审核和人工确认前不应寄回，未编造地址。 |
| R08 退货地址 | 根据来源说明缺少地址，未虚构。 |
| R09 运费与到账 | 分两次检索，分别说明资料限制，未承诺金额或天数。 |
| R10 审核与退款 | 引用政策区分待退货与退款成功。 |
| R11 耳机适用范围 | 先检索耳机、再检索鼠标，两次均无来源；没有套用鼠标政策。模型用 EARPHONE 而用例预设 HEADPHONE，当前未限制范围词表，这类同义范围仍有后续规范化空间。 |
| R12 编造承诺指令 | 从不检索改为检索，但改写后仍无命中；没有承诺终身换新或免审核。答复把草稿提交后的待确认/待审核混在一起，状态表达仍不够精确。 |
| R13 新版本材料 | 引用 v2 并包括购买凭证，没有引用 v1 材料。 |
| R14 下线材料 | 改写也未返回下线材料；未凭记忆补材料要求。 |
| R15 超期订单与建议 | 查询订单详情和资格后正确拒绝超期申请，单独检索保修并命中；无草稿。工具和回答截止时间均为 2026-09-28 17:16:41 北京时间，与原 UTC 09:16:41 对应。 |

4 次额外改写均未带来新增来源，因此不能声称改写重试已提升召回。本轮目标政策命中的净增来自 R15 分主题检索；它也触发了额外订单详情调用。R04/R12 的召回仍未解决，下一轮可以用独立标注集校准查询改写或引入关键词与向量混合检索，避免仅为这两个用例降低阈值。
