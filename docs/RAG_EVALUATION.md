## 如何执行

先确认 `http://127.0.0.1:11434` 已运行且 `bge-m3` 下载完毕。当前终端须能读取 `DEEPSEEK_API_KEY`；IDEA 的运行配置不会自动传给终端。可通过既有脚本的 `-KeyFile` 参数读取本机密钥文件，不要把密钥放进脚本或 Git。

```powershell
./scripts/Run-AgentBaseline.ps1 -RagEvaluation
```

普通 `mvn test` 不运行真实模型评测。该命令只运行 RAG 评测，不能与 `-DryRun` 或 `-KnowledgeTest` 合用。最多 15 个对话任务，每任务最多 8 次工具调用；不自动重试场景，不调用额外评分模型。工具调用可能导致一轮对话有多个供应商请求，不能把 15 轮等同于 15 次 HTTP 请求。

可靠性优化后，searchPolicies 可提供 fallbackQuestion：首次检索为空时，服务端每轮最多执行一次额外的同范围改写检索，不重试服务故障。它属于同一次工具调用，因此工具调用数不等于向量查询次数；实际采用的改写问题写在工具返回 message 中。原始问题直接检索的评测接口保持不变。

脚本使用临时 MySQL 33310 和 Redis 16382，运行结束后关闭。仅操作测试库中的合成政策和订单，不更改日常开发库。5 份固定政策通过真实发布接口分块、向量化和入库；R13 发布材料政策 v2，R14 下线材料政策，R15 查询签收 8 天的合成订单。

## 记录与解释

结果目录：`backend/target/agent-evaluation/rag-real-时间/`。

- `cases.json`：问题和预期依据，执行前固定。
- `corpus.json`：原始 5 份演示文档。
- `policy-versions.json`：最终文档版本，包括本轮发布的 v2；日期和 ID 随运行变化。
- `results.json`：逐场景原始检索、工具参数/结果、回答、实际来源、Token 和耗时。

直接检索评测用人工指定 scope 和原始问题；Agent 自行决定是否调用工具、如何改写问题和选择 scope，因此两条链路必须分别统计，不能把它们混成同一个命中率。

`expectedPolicyHit` 只衡量预先标注的目标文档是否出现在阈值以上 Top-4 中，不衡量片段的全部质量。没有指定目标文档的 R11/R14 不纳入命中率分母。`businessFailures` 检查任务完成、来源原文对应、范围/版本有效性、超期订单资格工具与不得建草稿等硬性条件；为空不代表回答完全可信。

回复还需逐条审阅是否有依据、是否引用真实来源、是否把演示政策当作真实承诺、资料不足时是否拒绝编造。原始报告保持 PENDING，助手审阅另存，不能称为独立人工盲评或自动 RAGAS 分数。

耗时包含本机接口、Ollama、模型与 SSE 处理。网关最后一次性发送正文，首次文本不是供应商首 Token 延迟。模型用量来自供应商响应，包含工具往返上下文，不等同于账单核验。每题只测一次，不宣称稳定准确率或生产性能。
