# 批量查询可售后商品

## 解决的问题

原来模型先分页调用 `listMyOrders`，再对每笔订单调用 `getAftersaleEligibility`。订单增加后，即使每次查询都成功，也可能触发单轮 8 次工具调用上限，导致没有最终回答。

新增 `listEligibleAftersaleItems(page)`，在后端用一条 SQL 查询当前登录用户的可售后商品，模型不需要逐笔筛选。系统提示词和工具描述均指引此类问题优先使用聚合工具；单个指定订单仍可使用原资格工具。8 次调用和 90 秒任务上限保持不变。

## 查询规则

- 与 RETURN_7D_V1 对齐：订单已完成、签收时间已到达且距现在不足 7 天、商品实付大于零、剩余数量大于零。
- 占用量包含待审核、审核通过、退回运输、收货、退款处理、退款失败以及已完成申请；拒绝或撤销不占用。
- 返回订单内部 ID、订单号、商品项 ID、名称、剩余数量和剩余总金额。金额不是单价，也不是最终退款承诺，提交申请时仍执行原有加锁校验。
- 按**商品项**分页，每页 10 项，查询 11 项判断 `hasMore` 和 `nextPage`。同一订单可能有多个商品，不能把商品项数当订单数。
- 有下一页时说明还有结果，用户要求继续后再查下一页，不自动遍历全部页面。并发业务变更可能改变分页内容，返回的是查询时的资格快照。
- 普通 REST 入口：`GET /api/aftersale-eligible-items?page=1`，需登录，不接受模型传入用户 ID。

## 错误提示

工具预算耗尽和任务停止使用类型化异常，业务层从异常因果链中识别原因，给出固定、脱敏的用户提示；响应超时、登录失效、模型服务或网络异常分别提示。前端沿用任务 `errorMessage` 展示，不把底层异常原文交给用户。已有失败任务不重新执行或改写记录。

## 验证与联调

运行 `scripts/Run-AgentBaseline.ps1 -AftersaleTest`。新增覆盖聚合与单笔金额一致、身份隔离、过期订单过滤、占用和撤销后的剩余数量、超过 10 项时的分页，以及一次聚合工具调用和预算耗尽文案。该脚本使用隔离数据库与模拟模型，不调用 DeepSeek。

重启 local 后端后，以 demo_customer 在新对话发送“查询可以售后的订单”。在客服执行监控中核对是否调用 `listEligibleAftersaleItems`；回复应包含可申请商品及其剩余数量、金额。真实模型的工具选择需要这一步联调确认，模拟测试不代表真实模型评测结果。
