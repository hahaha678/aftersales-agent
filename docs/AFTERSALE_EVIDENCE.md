# 售后图片凭证

## 使用步骤

1. 重启使用 `local` 配置的后端，Flyway 自动执行 V10，新建 `aftersale_evidence`；无需手动执行 SQL，不需要安装文件服务。
2. 买家打开“售后记录”中待审核申请的详情，找到“售后图片凭证”。选择图片、预览后点击“确认上传”。刷新页面后图片仍保留。
3. 客服打开对应审核详情，查看缩略图，点击图片放大，然后按照原有流程审核。
4. 审核通过、拒绝或买家撤销后，不再接受新图片，已有凭证仍可查看。完全相同的文件重试返回已有记录，不重复占用额度。

上传入口在正式申请详情，Agent 草稿确认提交后也可以从申请详情上传。本版用于人工审核，没有接入视觉模型，也不会把图片加入 DeepSeek 上下文。上传后保留，不支持编辑或删除；界面在上传前提供预览及说明。

## 规则与实现

- 每个申请最多 5 张、每张最多 5 MiB；仅 JPEG/PNG。最长边 6000 像素，总像素不超过 1600 万。
- 后端根据实际内容识别格式，先检查尺寸再解码，重编码去除元数据及附加内容。因此保存的是规范化图片，而非原文件逐字节副本。校验后的图片也不能超过 5 MiB。
- 原文件 SHA-256 用于同申请内去重，数据库唯一约束兜底。上传和审核共用订单行锁，并在锁内重新检查状态与数量。
- 图片内容存放 MySQL `MEDIUMBLOB`，元数据与内容同事务提交。列表查询不读取二进制；查看单张时才取内容。适合当前演示项目规模；图片量增长后应将内容迁移到私有对象存储，并补偿数据库和对象存储之间的失败。
- 买家仅访问本人申请；客服通过单独的 staff 接口查看。读取图片时同时校验申请归属和图片归属，不使用公开静态目录或 URL 中的令牌。
- 前端通过 Bearer 请求获取 Blob，创建临时 object URL；离开页面时取消请求并释放 URL。响应禁止缓存。数据库备份包含图片，容量规划需计入附件。

## REST 接口

| 方法 | 路径（省略 `/api`） | 用途 |
| --- | --- | --- |
| POST | `/aftersales/{id}/evidence` | 上传，multipart 字段 `file`；成功或去重均返回 200 |
| GET | `/aftersales/{id}/evidence` | 买家凭证列表 |
| GET | `/aftersales/{id}/evidence/{imageId}/content` | 买家读取图片 |
| GET | `/staff/aftersales/{id}/evidence` | 客服凭证列表 |
| GET | `/staff/aftersales/{id}/evidence/{imageId}/content` | 客服读取图片 |

Swagger 提供 multipart 文件选择；业务错误统一返回 JSON。超过 HTTP 上传限制返回 413，图片不合法返回 400，状态或数量冲突返回 409。

## 验证

`scripts/Run-AgentBaseline.ps1 -AftersaleTest` 使用隔离 MySQL/Redis，验证上传、去重、越权拒绝、客服读取、错误申请与图片组合、审核后拒绝追加、空文件、伪造 PNG、超大文件以及并发数量上限。测试不调用 DeepSeek，也不修改日常开发数据库。

`EvidenceImageTest` 额外检查实际格式识别、尾部内容清除与尺寸限制。前端执行 `npm run build` 和 `npm test`。
